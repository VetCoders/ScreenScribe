## 2. What Screenscribe already has (the "web" side) and what it lacks

Everything below is Python 3.11+ (`pyproject.toml`: FastAPI ≥0.115, uvicorn ≥0.32, python-multipart, websockets ≥17.1, httpx, typer; entry point `screenscribe = screenscribe.bootstrap:main`; installed with `uv tool install` via `make install`).

**Review server** (`screenscribe/review_server.py::create_review_app(output_dir, report_filename, video_path, config)`), launched by `screenscribe review` → `cli_serve._serve_report` (default port 8765, bind-probe for a free port, `uvicorn.run(host="127.0.0.1")`, opens `http://localhost:<port>/<quoted report_filename>#token=...` in the default browser, symlinks the video next to the report and unlinks it on exit). Routes: `GET /` → 307 to `/<report_filename>`; `GET /video` and `GET /<video_name>` (FileResponse of the selected video only); `GET /<report_filename>` (serves the on-disk HTML Pro report with the `<video src>` rewritten to `/video?st=<signature>`); `POST /api/stt` (browser-recorded audio → STT); `POST /api/manual-mark`, `PATCH|DELETE /api/manual-mark/{id}`, `POST /api/manual-analyze/{id}`, `GET /api/review-state`, `POST /api/reset-review`, `POST /api/save`; `app.mount("/", StaticFiles(output_dir, html=False, follow_symlink=False))` last.

**Analyze server** (`screenscribe/analyze_server.py::create_analyze_app(video_path, config)`), launched by `screenscribe analyze --port` (`cli.py:734–884`, same loopback + fragment-token pattern, `tokenized_url(f"http://localhost:{port}", ...)`). Routes: `GET /` (renders `shell.ANALYZE_SURFACE` via `render_surface`), `GET /video`, `POST /api/stt`, `POST /api/mark`, `GET /api/markers`, `GET /api/marker/{id}/frame` (signed `st`), `PATCH|DELETE /api/marker/{id}`, `POST /api/analyze/{id}`, `POST /api/finalize/start`, `GET /api/finalize/status/{job}`, `GET /api/finalize/result/{job}`, `POST /api/finalize`, `GET /api/export`, `GET /api/report/markdown`.

**HTML Pro** (`screenscribe/html_pro/{renderer,assets,data}.py` + `screenscribe/html_pro_assets/`): single-file report; CSS/JS/templates are inlined by `assets.load_asset` (`styles/report-pro.css`, `screenscribe-theme.css`, `screenscribe-theme.polish.css`, `analyze_dashboard.css`; `scripts/review_app.js`, `analyze_dashboard.js`, `video_player.js`, `i18n.js`, `lib/{stt-transport,language-control,tab-keyboard,layout-control}.js`; `templates/shell.html` + `partials/*.html`; vendored `jszip.min.js`). No external `<script src>`/`<link href>` to CDNs (census on renderer/assets/shell = 0 hits). `screenscribe/server/` exists on disk but holds only an empty `routers/` directory — not a module.

**Security model** (`screenscribe/server_security.py`, precisely):
- Bind is `127.0.0.1` only (uvicorn call sites in `cli_serve.py` and `cli.py`).
- Middleware `install_security(app, token, video_paths=...)` on every request: `Host` header must normalize to one of `localhost | 127.0.0.1 | ::1` (DNS-rebinding guard) → else 403.
- For `/api` and `/api/*`: `Origin` header, if present, must be localhost → else 403; then `X-ScreenScribe-Token` header must equal the per-process token (`secrets.token_urlsafe(32)`, `generate_session_token()`), compared with `secrets.compare_digest`; the single exception is `GET /api/marker/{id}/frame` which may carry `?st=HMAC-SHA256(token, "frame:<id>")` (`frame_access_token`).
- For the registered video paths: header or `?st=HMAC-SHA256(token, "video")` (`video_access_token`).
- Token delivery: URL fragment `#token=...` (`tokenized_url`); `review_app.js:12` / `analyze_dashboard.js:19` read `location.hash`, strip it, and patch `fetch` to add the header on same-origin `/api*` requests.
- No CSP header or `<meta http-equiv>` is emitted anywhere (census = 0). No CORS middleware. Upload cap on `/api/stt` via `server_common.install_stt_upload_cap` (`MAX_AUDIO_BYTES`).
- Microphone: `lib/stt-transport.js` uses `navigator.mediaDevices.getUserMedia` + `MediaRecorder` in the page and POSTs the blob to `/api/stt` — capture is browser-side, the server only transcribes.

**What is missing for a hosted mode** (facts, not opinions): no way to pass a pre-generated token in (`generate_session_token()` is called inside `create_*_app`, the token is read back from `app.state.session_token`); no `--token-file`/`--port-file` handshake for a parent process; no readiness signal beyond the console print; no `Content-Security-Policy`; the review flow requires the report to exist first (`_serve_report` returns early with "No <report> found") — there is no server route that runs the review pipeline itself; no single "serve" entry that can switch between analyze and review for a dropped file; `webbrowser.open` is unconditional on the analyze path (`cli.py:876`) and gated only by the `serve` flag on review (`cli.py:540–548`).

## 3. Target architecture

```
Screenscribe.app (AppKit, Swift 6)
 ├─ AppDelegate            menu bar, lifecycle, sidecar supervisor, URL scheme
 ├─ MainWindowController   window + unified toolbar   (lifted from shell-agent)
 │   └─ MainSplitViewController                        (lifted, 2 or 3 panes)
 │       ├─ SidebarViewController   native: recent videos / reports (NSTableView)
 │       ├─ TaflaViewController     WKWebView → http://127.0.0.1:<port>/…
 │       └─ InspectorViewController native: sidecar log tail, job progress (optional)
 ├─ SidecarSupervisor      Process(): bundled python -m screenscribe.hosted --token-file --port-file
 └─ Bridge (Swift)         WKScriptMessageHandler ⇄ page JS  (window.webkit.messageHandlers.screenscribe)
Contents/Resources/runtime/  private CPython + screenscribe wheel + deps  (same shape as vibecrafted 449af692)
```

**Shell.** Keep `MainWindowController`/`MainSplitViewController` as-is except: window title "Screenscribe", frame autosave name `ScreenscribeMainWindow`, canvas item replaced by `TaflaViewController`, inspector optional (min 250). `LSUIElement` flips to false (Screenscribe is a document-style app, not a menu-bar agent); keep the `NSStatusItem` only if a Founder asks — *recommendation: drop it in M1*.

**Canvas = `WKWebView`.** `WKWebViewConfiguration` with a non-persistent `WKWebsiteDataStore` per launch (nothing the page stores must outlive the token), `preferences.isElementFullscreenEnabled = true` (video), `mediaTypesRequiringUserActionForPlayback = []`, `userContentController` with the handlers below, and `navigationDelegate` that allows only `http://127.0.0.1:<port>/...` for the main frame and hands every other URL (`target=_blank`, external `https`) to `NSWorkspace.shared.open`. Initial load: `URL(string: "http://127.0.0.1:\(port)/#token=\(token)")` — the fragment path is exactly what the JS already reads, so the web assets need **zero** changes for auth in M1. `127.0.0.1` rather than `localhost` avoids an IPv6/`::1` first-try in WebKit; both pass the Host guard.

**Process model.** Two candidates:
1. Embedded CPython sidecar (the `vibecrafted-app` 449af692 shape: `uv python install <ver> --install-dir seed --no-bin`, copy into `Contents/Resources/runtime/python`, `uv pip install --target runtime/python-site screenscribe==<ver>` from the built wheel, `runtime/bin/python3` wrapper, sign every Mach-O, probe imports after signing). Already proven through notarization once in this workspace (script lines 540–645).
2. PyInstaller one-dir bundle.

*Recommendation: (1).* Reasons that are facts: the release script, path-normalization, `__pycache__` seal guard and notarization of an embedded CPython all exist and are exercised in `build-vibecrafted-release.sh`; Screenscribe's own install path is already `uv` (`make install`, `verify` runs `uv run`), so the dependency closure is the wheel + `uv pip install --target` — no second packaging tool, no hidden-import hunting for FastAPI/uvicorn/pydantic, and the same interpreter runs `screenscribe auth` (Lane B) from the CLI and from the app. PyInstaller adds a new toolchain and a new class of notarization failures (unsigned collected dylibs) without removing any step above. Cost of (1): ~40–60 MB of Python in the bundle and `ffmpeg` is still an external requirement (Screenscribe calls `ffmpeg` through `audio.py`/`detect.py`; bundling it is out of scope here and marked open in §6).

**Sidecar contract (new, Python side, `screenscribe/hosted.py` + a `screenscribe hosted` typer command):**
- Args: `--mode analyze|review`, `--video <path>`, `--output-dir <path>` (review), `--token-file <path>`, `--port-file <path>`, `--parent-pid <pid>`.
- Behaviour: token is **read from `--token-file`** (0600, written by Swift with `SecRandomCopyBytes`) instead of `generate_session_token()`; `create_*_app` gains an optional `session_token=` parameter that `install_security` records unchanged; port 0 → bind-probe as today → write the chosen port to `--port-file` atomically after uvicorn's `startup` event; never call `webbrowser.open`; exit when `--parent-pid` disappears (poll `os.kill(pid, 0)` every 2 s) or on SIGTERM.
- Swift `SidecarSupervisor`: `Process()` with `executableURL = runtime/bin/python3`, arguments `["-m", "screenscribe", "hosted", ...]`, environment reduced to `HOME PATH LANG TMPDIR` + `PYTHONNOUSERSITE=1 PYTHONDONTWRITEBYTECODE=1` (same list as `AppDelegate.firstRunEnvironment` at 449af692) + `SCREENSCRIBE_CONFIG_DIR` if Lane A/B introduce one; waits for the port file (timeout 15 s → `NSAlert` in the style of `reportWorkspaceLaunchFailure`), then loads the web view. Stdout/stderr piped to the inspector log tail and to `os.log` subsystem `io.vetcoders.screenscribe`. On `applicationWillTerminate`: SIGTERM, 3 s, SIGKILL.

**Bridge contract** — `WKUserContentController.add(handler, name: "screenscribe")`; page → native via `window.webkit.messageHandlers.screenscribe.postMessage({type, id, payload})`; native → page via `evaluateJavaScript("window.__screenscribeHost.dispatch(<json>)")`. Every message is a JSON object `{ "type": string, "id": string (uuid, request/response correlation), "payload": object }`. Message names:

| type (page→native) | payload | native action / reply type |
|---|---|---|
| `host.hello` | `{schema:"screenscribe.host.v1", page:"review"|"analyze"}` | reply `host.ready {version, capabilities:[...], platform:"macos"}` |
| `file.openDialog` | `{accept:["mov","mp4","m4v","webm"], multiple:false}` | `NSOpenPanel` → `file.selected {paths:[...]}` |
| `file.revealInFinder` | `{path}` | `NSWorkspace.shared.activateFileViewerSelecting` |
| `file.openExternal` | `{url}` | `NSWorkspace.shared.open` (https only) |
| `mic.requestAccess` | `{}` | `AVCaptureDevice.requestAccess(for:.audio)` → `mic.access {granted:bool}` |
| `notify.post` | `{title, body, identifier?}` | `UNUserNotificationCenter` request |
| `progress.set` | `{jobId, fraction 0..1|null, label}` | window `NSProgressIndicator`/dock badge |
| `auth.login` | `{provider:"openai"|"xai"}` | spawn `runtime/bin/python3 -m screenscribe auth login <provider> --json` (Lane B), stream `auth.event {provider, state:"code"|"pending"|"done"|"error", verification_url?, user_code?}` |
| `auth.status` | `{provider}` | spawn `screenscribe auth status <provider> --json` → `auth.state {provider, logged_in, account?, expires_at?}` |
| `auth.logout` | `{provider}` | spawn `screenscribe auth logout <provider>` → `auth.state` |
| `settings.get` / `settings.set` | `{keys}` / `{values}` | `UserDefaults` suite `io.vetcoders.screenscribe` → `settings.values {values}` |

Native → page (unsolicited): `host.fileDropped {paths:[...]}` (from `NSView` drag destination on the web view's parent, `NSPasteboard.PasteboardType.fileURL`), `host.sidecar {state:"starting"|"ready"|"exited", code?}`, `host.theme {appearance:"dark"|"light"}`. Drag-and-drop of a file onto the tafla is intercepted natively (the `WKWebView` is covered by a transparent `NSView` that implements `NSDraggingDestination` for file URLs only) so the page never receives a `file://` URL it cannot use — the native side then either restarts the sidecar in `analyze` mode for the new video or asks the page to switch, decided in M2.

**Token and keychain.** The session token is process-scoped and lives only in memory + the 0600 token file deleted after the sidecar reads it (sidecar deletes it after startup; Swift also deletes it on exit). Lane B's account tokens stay in Lane B's file store (`~/.config/screenscribe/accounts.json`, 0600) in M2; migrating that store to Keychain (`kSecClassGenericPassword`, service `io.vetcoders.screenscribe`, account `<provider>`) is an M3+ item that has to land in the Python CLI first, otherwise the CLI and the app would disagree about where the token is — the plan's non-goal "no keyring dependency (file store first; keychain in tafla host later)" is honoured.

**CSP and origin rules.** Two additions on the Python side, gated behind hosted mode so shared `file://` reports stay untouched: (a) response header `Content-Security-Policy: default-src 'self'; script-src 'self' 'unsafe-inline'; style-src 'self' 'unsafe-inline'; img-src 'self' data: blob:; media-src 'self' blob:; connect-src 'self'; frame-ancestors 'none'` — `'unsafe-inline'` is required because HTML Pro inlines all CSS/JS by design (`assets.py`); tightening to nonces is a later change to `renderer.py`; (b) `X-Frame-Options: DENY`. The WebKit side allows only `http://127.0.0.1:<port>` as main-frame origin and refuses navigation to `file:` and to anything else; `WKWebView` runs its own WebContent process, so the Host/Origin guards in `server_security.py` behave exactly as in Safari (Origin on `fetch` is `http://127.0.0.1:<port>` → passes `_origin_is_local`).

**What stays native.** File pickers and drop targets (`NSOpenPanel`, `NSDraggingDestination`); microphone permission (`NSMicrophoneUsageDescription` in `Info.plist` + `AVCaptureDevice.requestAccess`; WebKit's `getUserMedia` inside the page still needs the app-level TCC grant — see §6); main menu (File › Open…, Open Recent, Reveal in Finder; Edit standard responders so copy/paste works inside the web view; View › Toggle Sidebar/Inspector reuse the existing selectors); notifications; app updates (Sparkle or a hand-rolled appcast — not present in 449af692; the donor updates by re-installing the DMG, so this is new work and marked open in §6); Keychain; the sidecar lifecycle.

## 6. Risks and open questions

1. **App Sandbox vs sidecar Python.** The donor ships hardened-runtime *without* App Sandbox (no `.entitlements` in the tree; `codesign --options runtime` only). A sandboxed app cannot `Process()`-spawn an arbitrary interpreter that then opens a listening socket and reads user videos without heavy entitlement work. *Recommendation:* stay non-sandboxed, Developer-ID + notarization, direct distribution (DMG), no Mac App Store — same channel as vibecrafted. App Store is out of scope of this spec.
2. **`WKWebView` microphone.** `getUserMedia` inside `WKWebView` on macOS requires (a) `NSMicrophoneUsageDescription` in the host `Info.plist`, (b) the app-level TCC grant, and (c) on macOS 12+ the `WKUIDelegate` `requestMediaCapturePermissionFor:initiatedByFrame:type:decisionHandler:` callback answering `.grant`. Whether (c) alone suffices for an `http://127.0.0.1` origin or whether WebKit also demands a secure context is **unverified** here; if it refuses, the fallback is `mic.requestAccess` + native `AVAudioRecorder` capture posting to `/api/stt` from Swift (the endpoint is already multipart `audio`). To be measured in M2, not assumed.
3. **Notarizing embedded Python.** Proven once in this workspace (`build-vibecrafted-release.sh`), but every `.so` under `python-site` (pydantic-core, uvloop if pulled, httptools, websockets' C speedups) must be signed with hardened runtime + timestamp, and `--options runtime` can break CPython extensions that need `com.apple.security.cs.allow-unsigned-executable-memory` or `allow-dyld-environment-variables` — the donor does not set those entitlements and its shipped runtime (jsonschema, PyYAML, fastmcp) has fewer native extensions than FastAPI+pydantic. **Unknown** until the first `notarytool` log for a Screenscribe payload.
4. **`ffmpeg`.** Screenscribe calls `ffmpeg`/`ffprobe` on PATH; the app inherits the user's PATH only if launched from a shell. Bundle a signed `ffmpeg` in `Contents/Helpers` or hard-fail with a guided alert — open decision, affects M3 size and licensing (LGPL/GPL build flags).
5. **Code signing of dylibs / `install_name_tool`.** Not needed while there is no Rust dylib; `libpython3.12.dylib` is relinked with `@loader_path` in the donor script and that step carries over unchanged.
6. **Review pipeline inside the app.** `_serve_report` needs an existing report; the pipeline (`cli.review`) runs in-process in the CLI. Running it from the sidecar as a background job with progress (`progress.set`) means lifting the review pipeline behind an HTTP job API similar to `/api/finalize/start|status` in `analyze_server.py` — new Python work, scope decision for M2.
7. **Two servers, one window.** Analyze and review are separate FastAPI apps with separate tokens; switching modes means restarting the sidecar or mounting both under one app. Not decided here.
8. **Sparkle-style updates.** Nothing in the donor. New dependency (Sparkle 2 is sandbox-free-compatible and notarization-friendly) or manual DMG re-install. Open.
9. **macOS 27 "Tahoe".** No Tahoe-specific WebKit/AppKit behaviour was verified for this spec; the donor targets 14.0 and was built with Xcode 16. Treat as unknown; measure on the Founder's machines (Darwin 27.0.0 is the host this doc was written on).
10. **Localhost origin and `Origin: null`.** If WebKit ever sends `Origin: null` for fetches from the loopback page, `server_security._origin_is_local` will 403 (`urlparse("null").hostname` is `None` → `""` not in `_LOCALHOSTS`). Safari does not for `http://127.0.0.1`; to be confirmed against `WKWebView` in M1 (`tests/test_server_security.py` is the place to pin it).
